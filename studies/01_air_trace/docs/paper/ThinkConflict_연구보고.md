## 1. 연구 여정 — 선행 시도 V1–V3와 전환 (3–4p)

하나의 문제(시간 충돌 RAG)를 논문 타입을 바꿔가며 세 차례 공략했다.

| 버전 · 타입 | 무엇을 시도했나 | 무엇을 얻었나 | 왜 멈췄나 |
|---|---|---|---|
| **V1 · TV-RAG** 해결(Mitigation) | 올바른 시점 문서 선택만 보상하는 강화학습(GRPO) 보상 모델 | 규모·유형 무관 시간 충돌 취약성 실증 — 근거 오류율 > 정답 오류율 | LegalSearch-R1('26)에 거의 동일 선점 · 규칙기반·그래프가 이미 처리 |
| **V2 · 평가 맹점** 진단(Diagnosis) | 기존 인용 지표가 틀린 시점 문서 인용도 통과시키는 맹점 진단 | 표준 인용지표가 틀린 답도 통과(맹점) | 맹점 진단만으로는 기여 폭이 좁음 |
| **V3 · GoldCite** 지표(Metric) | 시점-유효 인용 지표 + 오류 진단 프레임 | — | 유사 지표(GaRAGe, ACL'25) 선점 · 시간충돌 사례 부족 |

**선행 실험이 남긴 결과** (4p):
- V1 파일럿 — GPT-4.1·Llama-3.1-70B, TC-RAG(무충돌 599·충돌 1,247): 충돌 문서 개입 시 정답 F1 0.81→0.65, 근거 정확도 0.74→0.57. **근거 정확도가 정답률보다 더 하락** → 정답만 보면 근거·시점 실패가 안 보임.
- V2 — 모델 5종, HoH 통제 219 + 실웹 51: **틀린 답의 81~100%를 인용지표가 '정상 인용'으로 통과**(GPT조차 100%). faithful-wrong 59~76%.
- 공통 발견: **정답(EM)은 맞혔지만 답과 근거가 따로 놀았다** → '어디서·왜 틀렸나'를 진단해야.

**ThinkConflict로의 전환**: 관측 대상(인용 지표 → 추론 궤적+답변 대조) · 충돌 범위(시간 충돌 → 일반 지식 충돌 전체) · 기여 수준(현상 측정 → 어디서·왜 틀렸는지 규명).

## 2. 서론 (5–8p)

### 2.1 문제 제기 (5p)

RAG 문서 충돌은 흔한데, 충돌 하에서 모델이 **'왜·어디서 맞고 틀렸는지'를 재는 진단 지표가 없다.** 같은 정답도 대조 추론 vs 우연이 섞이고, 같은 오답도 못 봄·오판·표출 실패가 한 숫자에 뭉개진다.

근거 ① 충돌은 흔하고 실재한다: DRAGged 40%(182/458, 실제 구글 검색 명시적 상충) · QACC 25%(381/1,617, 비모호 질문조차 문맥 충돌) · WikiContradict 50%(130/261 태그, 위키백과에도 모순 실재).
근거 ② 기존 지표(EM·정확도·ALCE류 인용 지표)는 '얼마나'만 잴 뿐 '왜·어디서'를 재도록 설계되지 않았다.

### 2.2 왜 이제 가능한가 — 추론 트레이스라는 진단 창구 (6p)

프롬프트 CoT는 사후 정당화 위험으로 출력 수준 자기일관성만 잴 수 있다(Turpin 2023 · Lanham 2023 · Parcalabescu & Frank 2024). 추론 모델은 `<think>`로 추론을 자발적으로 외부화하며, 트레이스를 직접 읽고 개입(재샘플링·절단)하는 방법론이 성숙했다(Bogdan 2025 · Macar 2025 · Korbak 2025).

**주장 범위**: 트레이스를 완벽한 거울로 전제하지 않는다. 주장은 **L-a(자기일관성)와 L-b(인과적 사용)에 한정**하고 L-c(내부 충실성)는 범위 밖(향후 연구).

| 수준 | 정의 | 측정/검증 | 사용 |
|---|---|---|---|
| **L-a 자기일관성** | 추론 결론과 최종 답변의 내용상 일치 | 추론 결론↔최종답 라벨 대조, 지표 AIR | RQ1 진단 · RQ2 경로 판별 · RQ3 대조 |
| **L-b 인과적 사용** | 추론이 답 결정에 실제로 영향을 주는가 | 절단·재생성 개입, 정답 한정 답 변화율 | RQ4 |
| L-c 내부 충실성 | 트레이스가 '진짜 속마음'인가 | 텍스트만으로 판정 불가 → **범위 밖** | — |

### 2.3 기여 (7p)

핵심 질문: **"RAG 충돌에서 완화 기법이 올린 정답률은, 진짜 대조 추론에서 온 것인가?"**

1. **완화 이득 분해 (핵심 발견)** — 늘어난 정답이 진짜 추론에서 왔는지 요행인지 문항마다 회계: LGR(정당 이득 비율) · HR(숨은 퇴행) · 경로별 취약성
2. **진단 프레임워크 (도구)** — 추론→답변을 탐지·해소·표출 3단계로 라벨링, 정답을 4경로(정상·도약·불협·맹목)로 상호배타 분류
3. **검증 — 충돌 고유성·인과성** — 대조군으로 난이도 아닌 충돌 고유 실패임을, 개입으로 추론이 답을 실제로 구동함(L-b)을 확인

### 2.4 연구 질문 (8p)

| 실험 | RQ | 질문 |
|---|---|---|
| 1 | **RQ1** 진단·불일치 위치 | 충돌 문맥에서 추론 결론과 최종 답변은 일치(L-a)하는가? 불일치는 어느 단계(탐지→해소→표출)에서 생기나? |
| 1 | **RQ2** 완화 기법 해부 | 완화로 늘어난 정답 — 진짜 추론인가, 우회 경로(도약·불협·맹목)인가? |
| 2 | **RQ3** 충돌 고유성 | 관측된 불일치는 충돌 고유 실패인가, 난이도·문서 수의 부수 효과인가? |
| 3 | **RQ4** 인과 규명 | 추론 결론이 최종 답변을 인과적으로 구동하는가(L-b)? |

## 4. 방법론

### 4.1 데이터셋 — 역할 분담과 공통 전처리 (10–14p)

세 데이터셋은 충돌 정의·문서 길이가 달라 **합치지 않고 분리 보고**한다.

| 데이터셋 | 성격 | 규모 | 라벨 확보 |
|---|---|---|---|
| **DRAGged** (Cattan '25) | 실제 구글 검색 문서, 전문가 5유형: outdated 62 · misinformation 5 · conflicting_opinions 115 · complementary 115 · no_conflict 161 (총 458) | 458 | 청크 라벨 없음 → LLM 초벌 + 사람 전수 검토 |
| **QACC** (Liu '25) | 구글 검색, 비모호 질문 25%가 문맥 간 충돌 (충돌 ≈404 / 비충돌 ≈1,213) | 1,617 | 정답·상충 답 쌍 내장 → 유형 부여 + 사이비(표기 차이) 충돌 스크리닝 |
| **RAMDocs** (Wang '25) | 위키 기반 + 오정보·노이즈 주입 (모호성 500 · 오정보 500) | 500 | 문서 type 내장 → 승계 (misinfo→conflict). 3요인 겹침 → 데이터셋 2개로 분리 |

**공통 전처리 5단계** (11p): 원본 구조 파악 → 필드 정규화(question·correct_answer·chunks[]) → 청크 라벨링(correct·conflict·noise) → 혼합 적재 → 사람 검증. `conflict_type`은 5개 라벨로 통일 부여 — DRAGged=native(전문가), RAMDocs·QACC=assign(LLM+인간).

### 4.2 진단 프로토콜 — 3단계 라벨과 지표 (15–16p)

| 단계 | 질문 | 라벨 |
|---|---|---|
| **L1 탐지** | 문서 간 불일치를 감지했는가? (+원인 유형까지 짚었는지 '유형 인지율') | detected / unrecognized |
| **L2 해소** | 정답 지지 문서를 유효하다고 결론지었는가? (시간→최신성, 오정보→권위) | correct / wrong / unresolved |
| **FA 표출** | 최종 답변에서 정답을 표출했는가? (동치 판정) | correct / wrong / abstain |

**정답의 4경로 분해** (16p): Legitimate(detected·correct — 견고) · Shortcut(detected·unresolved — 근거 약한 도약) · Discordant Hit(detected·wrong — 오답 문서 지지하고 정답) · Blind-Hit(unrecognized — 파라메트릭·우연).

**오답의 단계별 손실**: Loss_L1 = P(unrecognized) · Loss_L2 = P(L2≠correct | detected) · **AIR**(Answer Inversion Rate) = P(FA=wrong | L1=detected, L2=correct) — 결합확률과 분모 N 병기.

**라벨링 오염 통제** (15p): 결론은 마지막 명시적 문서 지지로 확정(없으면 unresolved) · 기권은 판정 제외+기권율 의무 보고 · 문자열 일치 아닌 정규화·동치 채점 · 복수 정답 any-gold.

### 4.3 실험 설계 (17–22p)

**대상 모델** (18p) — 네이티브 추론 모델만(SFT 증류 제외) · 20~32B 오픈 가중치 · 비양자화 · 추론 유무 교차:

| 모델 | 구조 | 추론 채널 | 역할 |
|---|---|---|---|
| **Qwen3.6-27B** | 27B Dense | `<think>` | 주력 — thinking on/off 하드 토글 |
| Gemma-3-27B | 27B Dense | 없음 | 교차 계열 일반화 (비추론 대조) |
| gpt-oss-20b | MoE 21B(활성 3.6B) | Harmony analysis | 교차 계열·MoE 검증 |

권장 디코딩 t=0.6, top-p 0.95 · 시드 5개 이상 · Paired Bootstrap 95% CI. 문항당 시드 k회 반복 → 최빈 경로 대표, 과반 미달은 '불안정' 분리 (19p).

**실험 1 (RQ1·RQ2)** — 평가 환경 5종 × 모델 3 × 데이터셋 3 → 환경별 전환 행렬 (19p):

| 환경 | 분류 | 예상 영향 |
|---|---|---|
| ① Standard RAG | 대조군 | 기저 |
| ② CAD(+AdaCAD) | 디코딩 (문맥 유무 로짓 대비) | L1/L2 |
| ③ CD2 | 디코딩 (충돌 자체를 분리·겨냥) | L2 |
| ④ Recency/Authority | 프롬프트 (date·url 우선 — RAMDocs 제외) | L2 |
| ⑤ Reflection | 프롬프트 (Self-RAG 반추 차용) | AIR |

RQ2 이득 분해 (20p) — 케이스별 전환 행렬(정상 L / 오답 W / 기권 A)에서:
- **LGR** = n(W→L) / (n(W→L)+n(A→L)) — 높으면 진짜 이득
- **HR** = (n(L→W)+n(L→A)) / Σn(L→j) — 클수록 숨은 퇴행
- **Flip** = (n(L→W)+n(W→L)) / N — 크면 내부 churn
- 종합: **LGR 높고 HR·Flip 낮은 케이스만 완화 이득을 신뢰**

**실험 2 (RQ3)** — 충돌 고유성 대조 (21p): ⓐ 원본(충돌) ↔ ⓑ 충돌 청크만 noise 교체(문서 수·난이도 동일) 짝 비교로 충돌 순효과 Δ=Acc(ⓑ)−Acc(ⓐ). ⓑ′ 위약 대조(무관 청크 교체)로 교체 행위 무해성 확인, ⓒ 자연 무충돌은 보정 후 동등성 검정(TOST) 참고용.

**실험 3 (RQ4)** — 추론 채널 격리·인과 개입 (22p): 1단계 thinking on/off 전환 행렬. 2단계 사전등록 개입 — Truncation(25·50·75% 절단, 0%=영점) · On-policy Resampling(문장 재생성, 판정 문장·AIR·Shortcut 위주) · Adding Mistakes(오류 삽입, 교차 검증) · Filler Tokens(길이 대조군). 모든 개입은 지점당 k회 재샘플링, '답 분포' 변화로 판정.

## 5. 예상 결과와 한계 (23p)

**예상**: ① AIR 실측·손실 단계 특정, 완화 이득 일부가 취약 경로에서 유래(LGR·HR·Flip로 드러남) ② 충돌만 제거한 ⓑ의 유의한 회복 = 충돌 고유 효과 ③ 개입 시 답 변화가 영점·filler 기준선 초과 = 추론이 장식이 아니라 답을 결정(L-b), thinking-off에서 AIR·Shortcut 소멸 시 추론 채널이 원인.

**한계와 대응**:
- thinking 모델에만 적용 가능 → thinking-off 조건을 대조군으로 병행
- 자연 충돌 표본 부족(182건) → N<20 셀 비교 제외(사전등록), QACC·RAMDocs로 보강
- 트레이스가 내부 추론을 다 반영하지 못함 → 이중 라벨링(κ) 전수 검증, AIR은 '써 놓고 어긴' 경우만 집계
- 개입은 출력 텍스트 단계에 한정 → 내부 활성화 개입은 향후 과제

## 6. 향후 연구 — 진단 결과에 따른 분기 (24p)

본 연구는 진단에 집중한다. 처방은 진단이 개입 지점을 특정한 뒤에야 근거를 갖는다.

| 진단 결과 | 의미 | 가능한 처방 |
|---|---|---|
| AIR ↑ | 병목이 추론→답변 전이부 | 엔트로피 스파이크 트리거 재디코딩 · 표출 직전 verifier 게이팅 · 정합성 정렬 학습 |
| LGR ↓ | 이득이 취약 경로 유래 | 경로 판정을 선택 필터로(재랭킹·rejection sampling) · LGR 직접 최적화 보상 |
| Shortcut ↑ | 정답이 지름길로 도달 | 답변 전 해소 단계 명시 강제 · 과정 보상(process reward)으로 도약 억제 |
| 추론 OFF 시 오류 소멸 | 원인이 추론 과정 자체 | 인과 지점 국소화 → 활성화 수준 개입 · 표적 완화 |
