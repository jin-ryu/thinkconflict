## 0. 연구 개요

**핵심 질문**: "RAG 문서 충돌에서 완화 기법이 올린 정답률은, 진짜 대조 추론에서 온 것인가?" (7p)

| 실험 | RQ | 질문 |
|---|---|---|
| 1 | **RQ1** 진단 | 추론 결론과 최종 답변은 일치(L-a)하는가? 불일치는 어느 단계(탐지→해소→표출)에서 생기나? |
| 1 | **RQ2** 이득 분해 | 완화로 늘어난 정답은 진짜 추론인가, 우회 경로(도약·불협·맹목)인가? |
| 2 | **RQ3** 충돌 고유성 | 관측된 실패는 충돌 고유인가, 난이도·문서 수의 부수 효과인가? |
| 3 | **RQ4** 인과 | 추론 결론이 최종 답변을 인과적으로 구동(L-b)하는가? |

**주장 범위** (6·8p): 트레이스를 완벽한 거울로 전제하지 않는다. 주장은 **L-a(자기일관성)·L-b(인과적 사용)에
한정**하고 L-c(내부 충실성)는 범위 밖. 인과 주장은 개입 실험에서만 세운다(§2.5).

## 1. 데이터 전처리

### 1.1. 데이터셋 3종과 역할 (10p)

세 데이터셋은 충돌 정의·문서 길이가 달라 **합치지 않고 분리 보고**한다.

| 데이터셋 | 성격 | 규모 | 문서 라벨 확보 |
|---|---|---|---|
| **DRAGged** | 실제 구글 검색 문서, 전문가 5유형 주석 | 458 (outdated 62 · misinfo 5 · opinions 115 · complementary 115 · no_conflict 161) | 규칙(correct만) → LLM 초벌 → **사람 전수 검토** |
| **QACC** | 구글 검색, 비모호 질문의 자연 충돌 | 1,617 (충돌 ≈404) | 정답·상충답 쌍 내장 → 유형 부여 + 사이비 충돌 스크리닝 |
| **RAMDocs** | 위키 기반 + 오정보·노이즈 주입 | 500 | 문서 type 내장 → 승계 (misinfo→conflict) |

### 1.2. 공통 파이프라인과 스키마 (11p)

원본 구조 파악 → 필드 정규화 → 청크 라벨링(correct·conflict·noise) → 혼합 적재 → 사람 검증.
모든 데이터셋은 아래 한 형태로 정규화된다 (`preprocessing/schema.py`가 정본):

```json
{
  "question_id": "dragged-0012",
  "dataset": "dragged",
  "question": "When does this year's Passover start?",
  "conflict_type": "outdated",
  "correct_answers": ["begins at sundown on Saturday, April 12."],
  "wrong_answers": ["April 22, 2024"],
  "chunks": [
    {"doc_id": 0, "text": "...begins before sundown on Saturday April 12, 2025.",
     "label": "correct", "date": "2025-01-01", "url": "https://hebcal.com",
     "supported_answer": "sundown on Saturday, April 12"},
    {"doc_id": 1, "text": "It starts at dusk on April 22, 2024.",
     "label": "conflict", "date": "2024-05-01", "url": "https://blog.example",
     "supported_answer": "April 22, 2024"},
    {"doc_id": 2, "text": "Passover is a Jewish holiday.",
     "label": "noise", "date": null, "url": null, "supported_answer": null}
  ],
  "exclusion_flag": null,
  "meta": {}
}
```

- `question_id`: `{dataset}-{원본 인덱스}`. 환경 간 짝짓기 키
- `conflict_type`: 5유형 중 하나 · `correct_answers`: any-gold용 복수 허용
- `wrong_answers`: conflict 문서들의 `supported_answer`에서 파생되는 캐시. **채점에는 쓰지 않는다**
  (오답 여부는 골드 동치 실패로 충분). 용도는 두 가지: ① 오답이 문서의 오정보를 채택한 것인지
  지어낸 것인지 구분하는 부가 관측(`adopted_wrong`) ② FA 판정자 이관 조건의 양다리 검출(§3.4)
- `exclusion_flag`: 채점 제외 사유(`no_match`·`date_tie`·`no_valid_conflict_pair` 등). null이어야 채점 트랙 진입
- 공통 규약:

- `conflict_type`: 5유형(`outdated`·`misinformation`·`conflicting_opinions`·`complementary`·`no_conflict`)으로
  통일. DRAGged = 전문가(native) · RAMDocs·QACC = assign(LLM+인간)
- `date`: **ISO-8601로 정규화 저장**. 상대 표기("2 days ago")는 코퍼스 최신 절대일 기준 환산(버리면
  최신성 해소가 구버전을 승자로 뽑는 실측 반례 있음), `NA`류는 부재 처리. 스키마 검증이 비-ISO를 거부
- `supported_answer`: **"이 문서가 주장하는 답"** (정답 아님). correct→정답 동치 답, conflict→그 문서의
  틀린 답, noise→비움(검증 강제). 여기서 문항의 `wrong_answers`가 파생된다
- **트랙은 플래그가 아니라 파일이다**: 충돌 유형별로 파일을 분리하고 채점 가능 여부는 `is_scorable()`
  (정답 존재 ∧ 제외 플래그 없음 ∧ 라벨 전부 확정)로 파생한다. 정답 없는 문항이 채점기에 들어가 전건
  오답 처리되는 사고를 구조로 차단
- 검토 CSV는 **`label` 단일 칸**: 규칙이 아는 값은 채워져 있고 LLM은 **빈칸만** 메우며(골드 매핑
  덮어쓰기 금지) 사람이 최종 수정. 출처는 `label_source` 참고 기록. `unknown` 잔존 문항은
  `unresolved_chunk_labels`로 채점 제외

### 1.3. 데이터셋별 변환: 원본 → 공통 스키마

각 변환 단계에 판정 주체를 명시한다. 규칙 = 결정적 코드, LLM = Mistral-Small-24B(§3.4의 오픈
판정자와 동일, 버전 고정), 사람 = 최종 확정 주체.

**DRAGged** (12p). 원본: `{question, conflict_type(전문가), correct_answer, search_results[{date, url, text}]}`

| 원본 → 공통 | 방법 | 비고 |
|---|---|---|
| question · text · url 승계 | 규칙 | |
| conflict_type(전문가 명칭) → 5유형 | 규칙 (명칭 매핑) | 전문가 주석이라 재판정 불필요 |
| correct_answer → correct_answers | 규칙 + 사람(정오표) | gold 오타("Boston Celtis" 등)는 사람만 교정 |
| date(5형식 혼재) → ISO-8601 | 규칙 | 상대 표기는 코퍼스 최신 절대일 기준 환산, `NA`는 null. 실측 date 보유 289/399 |
| label = correct | 규칙 (문자열+앵커 매칭, 최신성 해소) | 최신 매칭 전부 correct. 해소 불가는 `date_tie`·`date_absent`뿐. **오정보 충돌은 출처 권위 사안이라 자동 해소 금지 → 사람** |
| label = conflict/noise | **LLM 초벌 → 사람 전수 검토** | 규칙은 "다른 답 주장 여부"를 판별 불가 (실측: 정답 "at least 1,759"에 "1,762" 주장 문서) |
| supported_answer | LLM 초벌(라벨과 같은 호출) → 사람 검토 | 원본 부재 |
| wrong_answers | 규칙 (conflict 문서의 supported_answer 수집) | |

행동 트랙 대조군 = 비충돌 161(매핑 성공 145). 정답 없는 상보·의견 문항은 자기일관성 트랙 전용.

**QACC** (13p). 원본: `{question, contexts[], sources[], first/secondAnswer, first/secondContext(귀속), correctAnswer, reasons}`

| 원본 → 공통 | 방법 | 비고 |
|---|---|---|
| contexts → chunks.text, sources → chunks.url | 규칙 | **date 원본 부재 → 전건 null** (§2.3 환경 적용성 참조) |
| first/secondContext(문자 인덱스) → 답-문서 귀속 | 규칙 | |
| label | 규칙: correctAnswer 귀속 = correct, 다른 답 귀속 = conflict, **미귀속 = noise** | **주의**: 미귀속=noise는 주석 커버리지의 산물일 수 있음(실측 noise 54%, supported_answer 커버리지 46%). 미귀속 문서 층화 표본을 LLM+사람 스팟체크로 오분류율 추정·보고 |
| supported_answer | 규칙 (귀속 답 승계) | |
| conflict_type | 규칙 prior (reasons 코드 A = outdated, 나머지 misinfo 기본값) | 스키마 필수 필드의 초기값 채움. **확정·스크리닝은 포맷 변환이 아니라 §1.4 게이트의 일**이다 |

**RAMDocs** (14p). 원본: `{question, documents[{text, type, answer}], gold_answers, wrong_answers}`

| 원본 → 공통 | 방법 | 비고 |
|---|---|---|
| documents.type → label | 규칙 승계 (correct / misinfo→conflict / noise) | **LLM 재라벨 금지**: 골드를 추측으로 덮는 셈 |
| documents.answer → supported_answer | 규칙 승계 | |
| gold_answers → correct_answers, wrong_answers 승계 | 규칙 | 다중 골드는 any-gold(§3.2) |
| date · url | **원본 부재 → 전건 null** | Recency/Authority 환경 제외 근거 |
| 분해형 A / 결합형 B 분리, within-item 매칭 쌍 | 규칙 | `conflict = support+misinfo(k)+noise(n−k)` vs `control = support+noise(n)`, 문서 수 동일. 실측 338쌍. 초과 misinfo 절단은 meta 기록 |

**스키마 전환에서 알려진 문제와 대응** (재검토 결과):

1. **QACC date 전무**: 최신성(recency) 축이 QACC에서 공허 → Recency/Authority 환경은 QACC에서
   권위(url)만 적용됨을 §2.3에 명시하고 결과 해석에 반영
2. **QACC 미귀속=noise**: 주석이 없는 문서가 실제로는 답을 담을 수 있음(위 표의 스팟체크로 통제)
3. **RAMDocs 메타 전무**: date·url 기반 환경·해소 판정이 성립하지 않음(제외 명시)
4. **DRAGged 인력 부담**: 확정 필요 문서 563건의 LLM 초벌+사람 검토가 최대 병목(일정에 반영)
5. **gold 오타**: 어떤 단계에서도 퍼지 매칭으로 자동 수용하지 않음. 판정 단계에서는
   `gold_suspect`(§3.5 A9)로 에스컬레이션, 교정은 정오표(사람)만

### 1.4. 게이트: 채점 표본 선별

포맷 변환(§1.3)은 필드를 채우는 일이고, 게이트는 **어느 문항을 채점 트랙에 넣을지** 정하는 일이다.
게이트 판정은 문항을 지우지 않고 `exclusion_flag`로만 기록한다.

- **유효 충돌 게이트(공통)**: 정답 지지 문서와 충돌 문서가 공존해야 진입(`no_valid_conflict_pair`).
  통과율·최종 N을 검정력 표에 갱신
- **충돌 실재성 검사(공통, 규칙)**: conflict 라벨 문서의 `supported_answer`가 `correct_answers`와
  동치(§3.2 동치 규칙)이면 그 문서는 충돌 문서가 아니다. 해당 문서는 라벨 재검 플래그를 달고,
  재검 후 유효 충돌 게이트를 재평가한다. 파일럿 실측: RAMDocs 0/255 · QACC 1/208 · DRAGged 1/79 —
  주입 설계(RAMDocs)·전문가 주석(DRAGged)이 있어도 소량 누수가 있어 전 데이터셋에 건다.
  문항 수준 사이비 충돌(sharp/soft) 판정자 스크리닝이 추가로 필요한 것은 원본에 충돌 실재성
  주석이 없는 QACC뿐이다
- **QACC 스크리닝(투입 전 필수)**: ① sharp/soft 재분류: 먼저 **규칙 선별**(두 후보 답이 §3.2
  동치이면 soft 확정, 파일럿 실측 19/333문항) 후 잔여만 판정자 2종(Mistral-Small-24B + Claude,
  일치 시 확정, 불일치는 사람 adjudication. sharp만 투입) ② conflict_type 확정(§1.3의 규칙 prior를
  판정자 2종 일치 시 덮어씀 + 사람 스팟체크. 코드 B~F 미해독은 한계로 명시) ③ DRAGged 중복 48건
  제거 ④ correctAnswer 재검증(후보 대조는 규칙, 후보 밖 12건은 사람) ⑤ 문서 길이 공변량 기록
- **DRAGged**: 해소 불가(`date_tie`·`date_absent`)·무매칭(`no_match`)·라벨 미확정
  (`unresolved_chunk_labels`) 문항 제외

### 2.2. 공통 실행 설정

- 디코딩 **t = 0.6, top-p = 0.95 고정** · 시드 **5개 이상** · 문항당 시드 반복 후 **다수결 경로** 대표,
  과반 미달은 불안정 플래그 분리 (19p)
- **생성 형식 제약**: 모든 환경의 프롬프트에 "마지막 줄은 `Final answer: <답>`"을 동일하게 요구.
  채점은 그 줄(부재 시 마지막 문장)에만 적용한다. 파일럿 실측에서 답변 전문 채점 시 정답·오답 동시
  매칭이 26~85%였던 문제를 차단하기 위한 것이다. 프롬프트가 다르므로 **파일럿 결과와 직접 비교하지 않는다**
- 렌더링: 문서 무작위 셔플(셔플 시드 = 생성 시드에 결속: 위치 편향이 시드 반복에 걸쳐 평균화),
  `[Document i]` 표준 포맷, date/url 메타데이터 유지
- 생성 원문·doc_order·디코딩 설정 전부 JSONL 기록(재현성) · raw는 git 미포함, 집계 산출물은
  생성 즉시 커밋

### 2.3. 실험 1: 평가 환경과 전환 행렬 (RQ1·RQ2, 19p)

| 환경 | 분류 | 예상 영향 |
|---|---|---|
| ① Standard RAG | 대조군 | 기저 |

### 2.4. 실험 2: 충돌 고유성 대조 (RQ3, 21p)

- ⓐ 원본(충돌) ↔ ⓑ **충돌 청크만 noise 교체**(문서 수·주제·난이도 동일): 같은 문항 짝 비교로
  충돌 순효과 Δ = Acc(ⓑ) − Acc(ⓐ)
- ⓑ′ 위약 대조(무관 청크 교체): 교체 행위 자체의 무해성 확인
- ⓒ 자연 무충돌: 보정 후 동등성 검정(TOST). **참고용이며 결론 근거가 아니다**
- 추론 채널 기여는 thinking on/off 토글로 분리 (§2.5와 공유)

### 2.5. 실험 3: 추론 채널 격리·인과 개입 (RQ4, 22p)

1단계: 같은 문항 thinking on/off 전환 행렬 (Qwen 하드 토글 · gpt-oss 참고).
2단계 개입 (지점당 k회 재샘플링, '답 분포' 변화로 판정):

| 개입 | 역할 |
|---|---|
| Truncation (25·50·75%) | 주력: 답이 굳는 안정화 지점. 0% = 전체 삭제, 100% = 영점 |
| On-policy Resampling | 주력: 판정 문장이 답을 좌우하는가 (AIR·Shortcut 사례 위주) |
| Adding Mistakes | 보조: 오류 삽입 시 답이 따라가면 직접 증거 |
| Filler Tokens | 대조군: 내용 상실 vs 길이·형식 붕괴 분리 |

**게이트·해석 규칙**: `<think>` 전면 마스킹에서 답 분포가 안 변하면 진단 자체를 중단·재설계(go/no-go).
인과 기여 = 절단 효과 − 자연 종료점(no-op) 효과, filler 대조로 형식 교란 상한을 확인한 위에서만
해석. **텍스트 관측(AIR)으로 인과를 주장하지 않는다.** resampling 지점 국소화는 인접 문장
다지점 재생성으로 잡음 완충.

### 2.6. 자원 축소 우선순위 (사전 선언)

부족 시: ① 보강층(상관 분석·유형 인지) 축소 → ② 환경 5→3(디코딩 1 + 프롬프트 1 + 대조군) →
③ 시드 5→3(CI 유지). **완화 회계(RQ2)·대조군(RQ3)·개입(RQ4)은 사수.**

## 3. 평가 방법

### 3.1. 3단계 라벨과 이중 트랙 (15p)

| 단계 | 진단 질문 | 라벨 |
|---|---|---|
| **L1 탐지** | 문서 간 불일치를 감지했는가? | {detected, unrecognized} |
| **L2 해소** | 정답 지지 문서를 유효하다고 결론지었는가? | {correct, wrong, unresolved} |
| **FA 표출** | 최종 답변에서 정답을 표출했는가? | {correct, wrong, abstain} |

- **L2 결론 = 트레이스 내 마지막 명시적 문서 지지.** 없으면 `unresolved`. 암묵적 기울기는 부가
  라벨로만 기록, 번복 횟수는 부가 신호
- Loss_L1은 **"언어화된 인지 실패율"** 이라 명명한다. 쓰지 않은 인지는 재지 않는다는 한정을 담은 이름이다
- 부가 축인 유형 인지: detected일 때 원인 유형까지 짚었는가 {correct_type, surface_only}
- **이중 트랙**: 행동(정확도·AIR) 트랙 = 채점 가능한 사실 충돌 한정 / 자기일관성 트랙 = 명시적 상충
  전체, {유지·뒤집음·hedge}. 트레이스가 기울었는데 답변이 병기하면 불일치가 아니라 **hedge 별도 집계**

### 3.2. 채점 규칙

- **동치 판정**(문자열 EM 아님): 정규화(천단위 쉼표·하이픈·서수·괄호·마침표) + (i) 정규화 일치
  (ii) gold 포함 (iii) 날짜 동치 (iv) 수치 앵커 전부 + 내용어 60% 재현. **수치는 엄격**("November 20"
  ≢ "November 27th")
- **any-gold**: 복수 정답 중 하나를 지지·표출하면 correct
- **기권 분리**: abstain은 wrong과 구분, **AIR·오답률 분모 제외** + 기권율 의무 병기(환경 간 기권
  유도로 AIR을 낮추는 경로 차단, Reflection에서 특히 점검). 흐름 행렬 상태 공간에 기권 포함,
  정상→기권은 '퇴행-기권' 하위 집계
- **gold 오타는 규칙이 넘겨짚지 않는다**. 정오표(사람)로만 교정, 판정에서는 `gold_suspect`
  에스컬레이션(§3.5 A9)

### 3.3. 지표 (16·20p)

**정답의 4경로 분해** (상호배타·전수):

| 경로 | L1 | L2 | 해석 |
|---|---|---|---|
| Legitimate | detected | correct | 인지·해소를 거친 견고한 정답 |
| Shortcut | detected | unresolved | 명시적 해소 없이 도약한 취약 정답 |
| Discordant Hit | detected | wrong | 오답 문서를 지지해 놓고 낸 정답 |
| Blind-Hit | unrecognized | — | 인지 없이 도달 (파라메트릭·우연) |

**손실 지표**: Loss_L1 = P(unrecognized) · Loss_L2 = P(L2≠correct | detected) ·
**AIR** = P(FA=wrong | detected ∧ L2=correct ∧ 비기권). 조건부 지표는 항상 **결합확률·분모 N 병기**.

**RQ2 이득 분해** (케이스별 전환 행렬, L=정상 W=오답 A=기권):
LGR = n(W→L)/(n(W→L)+n(A→L)) · HR = (n(L→W)+n(L→A))/Σn(L→j) · Flip = (n(L→W)+n(W→L))/N.
**LGR 높고 HR·Flip 낮은 케이스만 완화 이득을 신뢰한다.**

**유형 인지율** = 유형 적중 충돌문항 / 전체 충돌문항.

### 3.4. 판정 체계

**원칙: 독해는 판정자, 결정은 규칙.** 판정자(LLM)는 독해 산출물(문장별 인용·입장, 동치 여부)만
내고, 정의의 적용("마지막 명시적 지지", any-gold, 기권)은 결정적 코드가 수행한다. 판정자가 최종
라벨을 직접 내는 방식은 금지.

**판정자 구성**: 오픈 판정자는 **어느 대상 계열에도 속하지 않는 제3 모델로 고정**(대상별 로테이션은
대상 간 비교에 판정자 차이가 교란으로 섞임):

| 역할 | 모델 | 비고 |
|---|---|---|
| 오픈 판정자 (고정) | **Mistral-Small-24B** (버전 고정) | 카나리아(§3.7) 통과를 채택 조건으로 하며, 미달 시 동급 제3 계열 교체 후 개정 이력 기록 |
| 상용 판정자 (고정) | Claude (API, 버전 고정) | 비용은 추정→승인→집행 |

Gemma·대상 모델은 판정자 금지 (`SAME_FAMILY` 코드 가드). 파일럿 판정은 gpt-oss 1종이었음을 보고에 명시.

**과제와 이관 조건** (하이브리드: 규칙 → 판정자 → 인간):

| 과제 | 판정자 입력 | 판정자 산출 | 이관 조건 |
|---|---|---|---|
| FA 동치 | 질문·gold·최종 결론 발췌 | gold 주장 여부 | 규칙 wrong 전수 · correct∧양다리 · abstain 전수 |
| L2 문장 스탠스 | 문장 분할 트레이스·문서 (**골드 라벨 비노출**) | 문장별 {문서, support/reject/neutral} 시퀀스 | 규칙 unresolved 후보 전수 |
| L1 인정 (부가 축) | 트레이스 | {yes/no} | 전수 (규칙 단서 축과 κ 비교용) |
| stance | 트레이스 결론·답변 | {유지/뒤집음/hedge} | hedge 규칙 실패 건. **전용 폼** |

**프로토콜**: 블라인드 시트(env·dataset·시드 컬럼 제거, 행 셔플) · 형식-채움 + 옵션 순서 무작위
스왑(50%) · temperature 0, 판정 1회 · **2종 일치 → 확정, 불일치 → 인간 adjudication** · 시트·프롬프트·
응답 전부 커밋. 세션 판정(Claude Code)은 **adjudication·스팟체크 전용**(주 판정 금지, 근거 기록,
"재현 불가" 명시, 가능하면 무맥락 새 세션이 수행).

### 3.5. 판정 기준서 (코드북): 판정자는 조항을 인용해 판정한다

판정 프롬프트에 아래 조항이 그대로 삽입되며, 출력은 **{라벨, 적용 조항 번호, 근거 발췌(입력에서
그대로, 40단어 이내)}** 3요소 폼이다. 근거가 입력에 실재하지 않으면 무효 → 재판정 1회 → 사람 큐.
예시는 파일럿(2026-08-21) 실측 사례다.

**과제 A. FA 동치**: `verdict ∈ {gold_asserted, other_asserted, abstain, gold_suspect}`

| 조항 | 규칙 |
|---|---|
| A1 결론만 판정 | 언급≠주장. 기각·비교하며 스친 답은 주장이 아니다 |
| A2 표기 변형 동치 | 대소문자·구두점·하이픈·서수·쉼표·날짜 형식·골드의 괄호 부가어 무시. "Jannik Sinner" ≡ "Jannik Sinner ( ITA )" |
| A3 고유명 철자 변형 | 같은 지시대상이 분명하면 1~2자 차이 동치. "Marti Frederiksen" ≡ "Marti Fredericksen" |
| A4 수치 | 골드가 근사 표현이면 범위 부합 수치 동치("3,028" ≡ "around 3000"), 정확 수치면 정확 일치만("November 20" ≢ "November 27") |
| A5 패러프레이즈 | 의미 동일 재서술 동치. "never officially given a proper name" ≡ "never given a name" |
| A6 부분 답 | 지시대상 특정 불가한 부분 문자열 비동치. "The Boy" ≢ "The Boy and the Heron" |
| A7 any-gold | 복수 골드 중 하나면 gold_asserted |
| A8 abstain | 확정 답 회피("문서에 없다"·"판단 불가"). 회피 표지+확정 답 병기는 그 답 기준(A1) |
| A9 gold_suspect | 답이 명백히 옳은데 골드가 틀려 보이면(오타·시점) 라벨 대신 gold_suspect → 정오표 큐. 예: 골드 "Boston Celtis" vs 답 "Boston Celtics" |

**과제 B. L2 문장 스탠스**: 문장별 `{sent_id, doc_ref, stance}` 시퀀스 (최종 L2는 규칙이 계산)

| 조항 | 규칙 |
|---|---|
| B1 명시적 인용만 | 문서를 특정한 문장만 doc_ref. 불특정 진술은 neutral |
| B2 같은 문장 귀속 | 지지/기각 표현은 같은 문장의 인용에만 귀속. "Doc 3's '1885' is a scraping error. I will trust Doc 2." → Doc 3 reject, Doc 2 support |
| B3 대조 구문 분리 | "ignore …, while Doc 2 is …": 각 절의 술어는 그 절의 문서에만 |
| B4 정의 | support = 채택·신뢰·최신·정확 평가 / reject = 구버전·오류·무관·기각 / 평가 없는 재진술 = neutral |
| B5 상충 평가 공존 | 한 문장이 같은 문서에 지지·기각 공존 → neutral + 플래그(사람 검수행) |
| B6 가정 제외 | "만약 Doc 1이 맞다면…" 가정 하 평가는 neutral |

**과제 C. L1 인정 (부가 축)**: `{yes/no}`

| 조항 | 규칙 |
|---|---|
| C1 정의 | 둘 이상의 문서가 같은 질문에 다른 답을 준다는 명시적 진술 |
| C2 나열 불인정 | 병렬 요약만 하고 차이를 짚지 않으면 no |
| C3 단서 어휘 불요 | "conflict" 없이도 실질("Doc 1 says 1902 but Doc 3 says 1885")이면 yes |

**과제 D. stance**: `{유지/뒤집음/hedge}`, 전용 폼

| 조항 | 규칙 |
|---|---|
| D1 | 트레이스 최종 기울기와 답변 주장(A1 기준)이 같으면 유지, 다르면 뒤집음 |
| D2 | 답변이 양쪽 대등 병기면 hedge. 뒤집음이 아니다 |
| D3 | 트레이스에 기울기가 없으면 판정 무효. 라벨을 지어내지 않는다 |

### 3.6. 사람 검수 (2층)

1. 검수 시트 = 판정 시트 + `human_label`·`human_note` 열. 검수자는 {라벨, 조항, 근거}를 **확인/정정**
   (백지 라벨링이 아님). 정정 시 잘못 적용된 조항 번호를 기록 → 조항별 오류율이 기준서 개정 근거
2. 범위: **AIR·Discordant 양성 전수 + 판정자 불일치 전수 + gold_suspect 전수** + 일치 건 층화
   표본(~200건, 인간 2인)
3. **κ < 0.7이면 라벨 정의를 수정해 재라벨링 루프.** 판정자↔사람 κ를 과제별·조항별 보고

### 3.7. 측정 도구 검증

- **카나리아 세트**: 정답 라벨을 아는 트레이스 50~100건(4경로 × 실패 유형, 합성+수동 라벨)으로
  라벨러(규칙+판정자)의 스테이지별 정확도/재현율을 측정, **본실험 결과와 함께 보고**. 판정자
  채택 조건(§3.4)이자 기준서 버전별 성적표
- 섭동 검사(지지 문장 앞 절단 → unresolved, 지지 문서 교체 → 라벨 반전)를 회귀 테스트로 상시 유지
- **운영 규칙 버전 고정**: 단서 목록·동사 목록·절 귀속 창은 코드가 정본이며, 본실험 시작 시점의
  `diagnosis/labeler.py`·`grading.py` 커밋 해시를 결과와 함께 보고

### 3.8. 보고 규칙

1. **유효 분모 N < 20 셀은 점추정·CI만 제시, 비교 주장 금지**
2. **데이터셋 풀링 금지**: 분리 보고
3. 시드 반복은 문항 분산을 못 줄이므로 **문항 부트스트랩(Paired Bootstrap 95% CI) 상시 병행**
4. 흐름 지표는 시드 다수결 경로 위에서, 불안정 플래그 분리 + 모드 비율 보고
5. LGR 분모 < 20이면 기법 pooled LGR 대체(점추정 병기)
6. **환경 간 AIR 비교는 공통 분모 paired 비교를 병기한다**. AIR 분모(L1∧L2 통과)가 처치의 영향을
   받으므로(파일럿 실측: 83→141), 두 환경 모두 분모에 든 공통 문항 짝 비교 없이 환경 간 AIR
   차이를 주장하지 않는다
7. 기권율은 AIR과 나란히 의무 보고
8. `results/` 집계 산출물은 생성 즉시 커밋(지표 계산 시점 증빙), raw는 git 미포함
