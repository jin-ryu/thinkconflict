# ThinkConflict 사전등록 규약 (Preregistration)

> 이 문서는 실험 데이터를 생성하기 **전에** 라벨 규약·게이트 기준·해석 규칙을 못박는 사전등록이다.
> 커밋 타임스탬프가 "실험 전에 확정했다"의 물증이다. 실험 후 규약을 바꿔야 할 경우 기존 항목을
> 지우지 않고 문서 말미 **개정 이력**에 무엇을·왜 바꿨는지 남긴다.
> 각 조항의 근거·상세는 정본 계획서(`연구계획서_ThinkConflict.md`)의 해당 절을 §로 인용한다.
> 최초 등록일: 2026-07-10

## 1. 라벨 규약 (Labeling Protocol)

### 1.1. 3단계 라벨 정의 (§3.2.1)

| 단계 | 진단 질문 | 라벨 |
|---|---|---|
| **L1 탐지** | 문서 간 불일치를 감지했는가? | {detected, unrecognized} |
| **L2 해소** | 정답 지지 문서를 유효하다고 결론짓는 올바른 추론을 했는가? | {correct, wrong, unresolved} |
| **FA 표출** | 최종 텍스트에서 정답을 표출했는가? | {correct, wrong, abstain} |

부가 축 — 유형 인지: L1 = detected일 때 원인 유형(시간/오정보/관점)까지 짚었는가 {correct_type, surface_only}.

### 1.2. 결론 확정 규칙 (§3.2.1)
- L2 결론은 **트레이스 내 마지막 명시적 문서 지지**로 확정한다.
- 마지막까지 명시적 지지가 없으면 `unresolved`로 라벨한다. 암묵적 기울기(leaning)는 부가 라벨로만 기록하고(부록 A(c)2) L2 본 라벨에 합치지 않는다.
- 번복 횟수는 부가 신호로 기록한다(부록 B 연계).

### 1.3. 기권 분리 (§3.2.1)
- 확정 답을 내지 않은 `abstain`은 `wrong`과 구분하며, **AIR·오답률 분모에서 제외**하고 별도 기권율로 보고한다.
- 완화 기법이 L2 = correct 문항의 기권 유도로 AIR을 인위적으로 낮추는 경로를 차단하기 위해, **환경 간 기권율 차이를 AIR과 나란히 의무 보고**한다(Reflection 환경에서 특히 점검).
- 흐름 행렬(전→후)의 상태 공간에 기권을 명시적 상태로 포함하고, 정상 경로→기권 이동은 '퇴행-기권' 하위 항목으로 집계한다(§3.3.2).

### 1.4. 동치 채점 (§3.2.1)
- FA의 `correct`는 답변 정규화(별칭·수치·날짜 형식 통일) + 동치 판정을 거친 **정확도(accuracy)** 다. 엄밀 문자열 EM이 아니다(표기 노이즈가 AIR로 새는 것 방지).
- 계획서에서 'EM'으로 약칭한 표면 지표는 전부 이 동치 판정 기반 정확도를 뜻한다.

### 1.5. 다중 정답 (any-gold) (§3.1.2)
- RAMDocs처럼 유효 정답이 복수인 문항의 L2·FA `correct`는 **정답 집합 중 어느 하나를 지지·표출한 경우**로 정의한다.

### 1.6. 4경로 분해 — 상호배타·전수 (§3.2.2(1))
정답(FA = correct)은 아래 네 경로 중 정확히 하나에 귀속된다.

| 경로 | L1 | L2 |
|---|---|---|
| 정상 (Legitimate) | detected | correct |
| Shortcut | detected | unresolved |
| Discordant Hit | detected | wrong |
| Blind-Hit | unrecognized | — |

### 1.7. 단계별 손실 지표와 분모 병기 (§3.2.2(2))
- Loss_L1 = P(L1 = unrecognized), Loss_L2 = P(L2 ≠ correct | L1 = detected), **AIR** = P(FA = wrong | L1 = detected, L2 = correct, 비기권).
- 조건부 지표는 항상 **결합확률과 분모 N을 함께 보고**한다(부분모집단 차이로 인한 오도 방지).
- Loss_L1은 **"언어화된 인지 실패율"** 로 명명한다. 유도 프로브 결과(침묵 상한/무능 하한 분해)는 Loss_L1 값 자체를 바꾸지 않으며 참고용으로만 병기한다(부록 A(c)1).

### 1.8. 이중 트랙 (§3.2.2(2) 측정 기준점)
- **행동(정확도·AIR) 트랙**: 채점 가능한 사실 충돌에 한정.
- **자기일관성 트랙**: 명시적 상충 전체로 확장. 답변 입장 라벨은 {유지, 뒤집음, 균형 병기(hedge)} 3분류 — 트레이스가 기울었는데 답변이 병기하면 불일치가 아니라 **hedge로 별도 집계**한다.

## 2. 검정력·보고 규칙 (§3.2.3)

1. **유효 분모 N < 20인 셀은 점추정과 CI만 제시하고 환경·모델 간 비교 주장을 세우지 않는다.**
2. 비교 주장은 QACC 게이트 통과분·RAMDocs(500)로 분모를 확보한 위에서 수행하고, DRAGged 자연 사실 충돌(채점 가능 56~61건)은 방향 일치 확인용으로 쓴다.
3. **세 데이터셋은 풀링하지 않고 분리 보고**한다(충돌 정의·문서 수·길이·메타데이터 가용성 상이).
4. 시드 반복(≥5)은 문항 분산을 줄이지 못하므로 **문항 부트스트랩을 항상 병행**한다(Paired Bootstrap 95% CI).
5. 흐름 지표는 문항별 **시드 다수결 경로** 위에서 정의하고, 다수결 과반 미달 문항은 **불안정 플래그**로 분리 집계하며 시드 간 경로 일치도(모드 비율)를 보고한다(§3.3.2).
6. LGR 분모("baseline 오답 ∧ 완화 후 정답")가 기법별 20 미만이면 **기법 pooled LGR**(기법별 점추정 병기)로 대체 보고한다.

## 3. 게이트 (실험 진행 조건)

### 3.1. 유효 충돌 게이트 (Phase 1 산출물 검증)
- 공통 스키마 문항이 채점 트랙에 들어가려면 **정답 지지 문서와 충돌(반대 입장) 문서가 공존**해야 한다. 통과율과 데이터셋별 최종 N을 확정해 검정력 표(§3.2.3)를 갱신한다.

### 3.2. DRAGged 골드 매핑 규칙 (§3.1.1(4))
- 정답 문서 자동 매핑(문자열+NLI)은 1차 초안이며, 행동 주장이 걸린 사실 충돌 문항은 **전수 인간 검증·교정한 골드 매핑**을 쓴다(정답 정오표 교정 포함).
- **복수 매칭은 제외 사유가 아니라 해소 대상**: 매칭 문서 중 `date` 최신성(+정답 지지)으로 유효 문서를 선정한다. 날짜 동률·부재로 해소 불가한 문항과 무매칭 문항만 플래그하여 L2 의존 지표에서 제외하고 건수를 보고한다.

### 3.3. QACC 스크리닝 게이트 (§3.1.3(4)) — 투입 전 필수
① sharp/soft 재분류(LLM 판정자 2종 + 인간 스팟체크; sharp만 채점 트랙 투입) ② DRAGged 질문 중복 47건 제거(판정 불일치 27건은 경계 사례로 보고) ③ `correctAnswer` 재검증 ④ 문서 길이 공변량 기록(스니펫 한계 통제) ⑤ 셔플링·표준 렌더링.
- 유료 API 판정자는 **비용 예측·승인 후에만 집행**한다(부록 D).

### 3.4. go/no-go — 전면 마스킹 게이트 (Phase 2, §3.3.3(b))
- `<think>` 전체 마스킹 시 답 분포가 유의하게 달라지지 않으면 사고 채널이 답과 무관한 장식이므로, **사고-답변 진단 자체를 중단하고 재설계**한다.

### 3.5. 라벨 신뢰도 게이트 (§3.2.1, 부록 A)
- 판정자는 대상 모델과 **다른 계열** 2종(오픈 1 + 상용 1), 옵션 순서 무작위 스왑, 형식-채움 프로토콜.
- 인간 2인 검증: **AIR·Discordant Hit 양성 전수 + 나머지 셀 층화 표본(합계 ~200건)**.
- L2 라벨 κ < 0.7이면 라벨 정의를 수정해 **재라벨링 루프**를 돈다. 판정자 불일치 문항은 인간 adjudication으로 확정한다.

### 3.6. 치환 증강 트랙 게이트 (부록 C, 예비)
- 자연 사실 충돌과 증강 표본의 Loss_L1 분포가 유사한 **난이도 동등성**을 확인한 뒤에만 본 실험(RQ3 세 번째 매칭 근거)에 투입한다. 시간형 변형은 본문 시제·정황 단서 정합까지 검수한다.

## 4. 인과 해석 규칙 (§3.3.4)

- **인과 기여 = 절단 효과 − 자연 종료점(no-op) 효과**로 정의한다.
- **filler-token 대조로 형식 교란의 상한을 확인한 위에서만** ΔAccuracy를 사고의 인과 기여로 해석한다.
- 인과 주장은 개입 실험(truncation·on-policy resampling)에 한정하며, 텍스트 관측(AIR 등)으로 인과를 주장하지 않는다(§1.3 L-a/L-b 경계).
- resampling 지점(L2 문장) 국소화는 판정자 의존이므로 인접 문장 다지점에서 함께 재생성해 국소화 잡음을 완충한다.

## 7. 원본 실측 반영 (2026-07-10, 실험 데이터 생성 전)

전처리 단계에서 원본 파일을 실측한 결과, §1~§3의 규약만으로는 판정이 확정되지 않는
지점이 드러나 아래 규칙을 **실험 생성 전에** 추가로 못박는다. §1~§3의 기존 조항은
수정하지 않는다.

### 7.1. DRAGged 최신성 해소의 '해소 불가' 정의 (§3.2 보강)
매칭 문서가 최신 날짜를 공유하더라도 **그보다 오래된 매칭 문서가 남아 있으면**
최신본과 구버전을 가를 수 있으므로 해소 성공으로 본다(최신본 전부를 `correct`로 둔다).
해소 불가는 매칭 문서를 날짜로 전혀 나눌 수 없을 때뿐이다:
`date_tie`(매칭 문서 전부가 동일 날짜) 또는 `date_absent`(날짜 전무).
**오정보 충돌은 최신성이 아니라 출처 권위로 갈리므로 자동 해소하지 않고 전수 인간 판정에 넘긴다.**

실측: 사실 충돌 67건 = 자동 해소 50 + 인간 검증 대기 11(무매칭 6 + 오정보 복수 매칭 5)
+ 날짜 해소 불가 6. **채점 가능 상한 61건** (계획서 사전 점검 예상 56~61에 부합).

### 7.2. DRAGged 행동 트랙 대조군 (§2.2 보강)
계획서 §3.3.3은 비충돌 대조군을 "상보 115 + 비충돌 161"로 적었으나, 실측 결과
**상보 115건 중 108건, 의견 115건 중 113건은 `correct_answer`가 비어 있다.**
따라서 정답이 필요한 **행동(정확도·AIR) 트랙의 대조군은 비충돌 161건(그중 골드 매핑
성공 145건)** 으로 한정하고, 정답 없는 상보·의견 문항은 **자기일관성 트랙 전용**으로 쓴다
(§1.8 이중 트랙과 정합). 이 축소를 한계(§5)에 명시한다.

### 7.3. RAMDocs within-item 매칭 쌍 구성 (§3.1 보강)
노이즈 문서는 질문에 종속된 지문이라 다른 문항에서 빌려올 수 없다. 따라서 매칭 쌍은
같은 문항 안에서만 만든다. misinfo m개·noise n개일 때 k = min(m, n)으로,
`conflict = support + misinfo(k) + noise(n−k)`, `control = support + noise(n)`.
두 변형의 **문서 수가 동일**해 충돌 유무만 다르다. m > n인 문항은 초과 misinfo가
conflict 변형에서 빠지므로 `meta.misinfo_dropped`에 기록하고, n = 0인 문항은 쌍을 만들지 않는다.

실측: 매칭 쌍 338개 (문서 수 불일치 0), 노이즈 부재로 제외 75문항, misinfo 일부 절단 17문항.
분모 338 ≥ 20이므로 §2.1의 비교 금지선에 걸리지 않는다.

### 7.4. QACC 충돌 정의·유형 부여 (§3.3 보강)
- **충돌 판정**: `secondAnswerExist == "A"` (실측 381건, 답 2/3/4개 = 243/94/44 —
  계획서 §3.1.3(2) 실측치와 일치).
- **유형 부여**: 원 레포에 `reasons` 코드북이 없다. 코드 `A`가 정확히 48건이고
  `explanation`의 최신성 키워드 적중률이 39.6%(타 코드 2.9~7.5%)로 계획서의
  "최신성 사유 48건"과 일치하므로 **`A` = 최신성(temporal)으로만 확정**하고,
  나머지 코드는 사실 충돌(`misinfo`)로 묶는다. **B~F의 의미는 미해독**이며,
  이는 유형 인지(§1.1 부가 축) 분석의 한계로 §5에 명시한다.
- **게이트 ② 실측**: DRAGged 질문 중복 48건 제거(계획서 47), 그중 DRAGged가 비충돌로
  판정한 경계 사례 28건(계획서 27) — 두 벤치마크의 충돌 판정 불일치로 별도 보고.
- **게이트 ③ 실측**: `correctAnswer`가 후보 답 집합에 없는 문항 12건 → 재검증 대상.
- 추가 플래그: 정답 지지 문서와 상충 문서가 공존하지 않는 53건은 유효 충돌 게이트(§3.1)
  미통과로 `no_valid_conflict_pair` 플래그를 달고 채점 트랙에서 제외한다.
- 종합: 중복 제거 후 333건 중 **플래그 65건을 제외한 268건**이 게이트 ①(sharp/soft)
  판정 대상이며, sharp 판정분만 채점 트랙에 들어간다(보수 가정 50% ≈ 134건).
  계획서의 "보수 가정 ≈167건"보다 작아질 수 있으므로, 스크리닝 후 검정력 표를 갱신한다.

### 7.5. DRAGged 날짜 정규화 (§7.1 보강)
원본 `date` 필드는 네 형태가 섞여 있다(사실 충돌 623문서 기준): ISO 202 · 자연어 절대일 223
· `"NA"` 181 · 상대 표기(`"2 days ago"`) 9. 규칙을 다음과 같이 고정한다.
- `"NA"`·빈칸·`none`류는 **날짜 부재**로 취급하고 최신성 비교에서 제외한다.
- 상대 표기는 크롤 시점 기준이므로 **코퍼스 내 최신 절대일(실측 2025-04-03)을 기준점**으로
  절대일로 환산한다. 이 문서들은 대개 최신본이라 그냥 버리면 최신성 해소가 구버전을 승자로
  뽑는다(실측 반례: "What date is Thanksgiving this year?" — 최신 문서가 `"5 days ago"`).
  환산으로 `date_absent` 1건이 회수되어 채점 가능 상한이 61 → **62건**이 되었다.

### 7.6. DRAGged 청크 라벨: 규칙이 단정하지 않는 범위 (§7.1 보강)
정답 문자열·앵커 매칭은 "이 문서가 **정답을 담았는가**"만 판정할 수 있고,
"**다른 답을 주장하는가**(conflict)"와 "무관한가(noise)"를 구분하지 못한다.
실측 반례: 정답이 `"at least 1,759"`인 문항에서 `"1,762"`를 주장하는 문서는 정답 문자열이
없어 매칭에 실패하지만 명백한 충돌 문서다. 규칙이 이를 `noise`로 단정하면 **유효 충돌
게이트가 무너진다**(실측: 플래그 없는 50건 중 10건에서 충돌 문서가 0개로 집계됨).

따라서 초안(`draft`)에서 규칙은 **`correct`만 확정**하고 나머지 문서의 `label`은 **빈칸**으로
남긴다(규칙 힌트 `matched_older`/`unmatched`는 참고로만 기록). `conflict` vs `noise`의 확정은
**LLM 초벌 → 사람 전수 검토**가 담당한다(PPT 12p ①).

라벨을 적는 칸은 검토 CSV의 **`label` 하나**다 — 규칙이 아는 값은 미리 채워져 있고, LLM은
**빈칸만** 메우며(규칙의 골드 매핑을 덮어쓰지 않는다), 사람은 아무 칸이나 고쳐 쓴다.
CSV에 적힌 값이 그대로 최종본이 되며, 누가 채웠는지는 `label_source`(rule/llm/사람)에
참고로 기록한다. 빈칸으로 남은 라벨은 `unknown`이 되고, `unknown`이 남은 문항은
`unresolved_chunk_labels`로 플래그해 채점 트랙에서 제외한다.

실측: 사실 충돌 67문항 623문서 중 규칙이 `correct`로 확정한 것은 60문서,
**확정 필요 문서 563건**이 LLM 초벌 + 인간 검토 대상이다.

### 7.8. 공통 스키마 정규화: `date`와 `supported_answer` (§3.1 보강)
세 데이터셋을 하나의 구조로 표준화하기 위해 두 필드의 형식·의미를 못박는다.

**`date` — ISO-8601(`YYYY-MM-DD`)로 정규화해 저장한다.**
DRAGged 원본은 실제 웹 크롤 결과라 표기가 뒤섞여 있다(문서 4,212개 실측):
`NA`/없음 53% · 자연어(`Nov 2, 2024`) 22% · ISO 18% · ISO+시각 7% · 상대표기(`2 days ago`) 1%.
최신성 해소가 이 값을 비교하므로 **저장 시점에 형식을 통일**한다. 상대 표기는 코퍼스 최신
절대일(실측 2025-04-03) 기준으로 환산하고(§7.5), 파싱 불가·부재는 빈칸으로 둔다.
스키마 검증이 비-ISO 값을 거부한다. RAMDocs·QACC는 원본에 날짜가 없어 전건 빈칸이다.

**`supported_answer` — "이 문서가 주장하는 답"이다 (정답이 아니다).**
- `label = correct` → 정답과 동치인 답
- `label = conflict` → 그 문서가 내세우는 **틀린 답** (구버전 날짜·오정보 등)
- `label = noise` → 질문에 답하지 않으므로 **비운다** (스키마 검증이 강제)

원본 가용성이 달라 채우는 주체가 다르다: RAMDocs는 `documents[].answer`, QACC는 답변-문서
귀속 주석에서 승계하고, **DRAGged는 원본에 없으므로 LLM 초벌이 `label`과 함께 뽑는다**
(같은 문서를 어차피 읽으므로 추가 호출 없음). 이로써 세 데이터셋이 동일한 의미의 필드를 갖는다.
이 필드에서 문항의 오답 목록(`wrong_answers`)이 파생된다.

### 7.7. 동치 채점 규칙 (§1.4 구체화)
DRAGged gold 문자열 실측: 대부분 짧지만(중앙 2단어) **사실 충돌 67건 중 10건이 문장으로
서술**돼 있고(`"For 2025 it is November 27th"`), 하이픈 5·서수 4·괄호 2·마침표 12건이 섞여 있다.
서술형 gold에 모델이 핵심만 답하면(`"November 27, 2025"`) 단순 포함 검사가 오답 처리해
**AIR이 표기 노이즈로 부풀려진다**(실측: 정답 사례 9건 중 6건이 오답 처리됨). 규칙을 고정한다.

- **정규화**: 천 단위 쉼표 · 하이픈 · 서수(`27th`→`27`) · 괄호 · 마침표를 접는다.
- **동치 판정**: (i) 정규화 일치, (ii) gold가 답변에 포함, (iii) 날짜 동치, 또는
  (iv) 답변이 gold의 **수치 앵커를 전부** 담고 gold의 연속 부분이거나 내용어의 60% 이상을
  재현한 경우. **수치는 엄격히 요구**하므로 `"November 20"`을 `"November 27th"`의 동치로
  받지 않는다(오탐 방지 — 실측 반례 6건으로 검증).
- **gold 오타는 규칙이 넘겨짚지 않는다.** `"Boston Celtis"`·`"Bolovia"`는 정오표(사람)가
  교정해야 채점 가능하다 — 퍼지 매칭으로 자동 수용하면 진짜 오답까지 받게 된다.

### 7.8. 판정자 비용 (§3.3 보강)
QACC 게이트 ①의 판정 대상은 333문항이며, 판정자 2종 기준 입력 약 57만 토큰·출력 약 10만 토큰으로
추정된다. DRAGged 청크 초벌(§7.6)은 623문서 × 판정자 1종이다.
**오픈 가중치 판정자로 수행하면 비용이 발생하지 않는다.** 상용 판정자를
쓰는 경우에만 단가를 곱해 승인 후 집행한다.
